# Plan: hard-code every provider type and remove autogen altogether

## Goal

Make every OANDA provider type, enum, and endpoint method in `src/` ordinary
hand-maintained Rust, and delete the code-generation tooling. The checked-in
sources become the only artifact; nothing in the repository claims they can be
regenerated. Tracked against
[#21](https://github.com/SharurTrading/oanda-rs/issues/21), whose item 2 this
supersedes (see Step 7).

## Why now (evidence)

- The generators are already a one-off bootstrap, not a living pipeline:
  `tools/generate_api.py`, `tools/generate_models.py`, and
  `tools/generate_variants.py` require `lxml` plus saved OANDA HTML pages in
  `/private/tmp`. Neither is in the repository or CI; CI runs only
  `tools/check_coverage.py` and the offline Python tests
  (`.github/workflows/ci.yml`).
- The checked-in code has diverged from generator output. The generator still
  emits the old `self.execute(Method::…, account, …)` call, while
  `src/order.rs` passes `MutationAdmission::Ordinary(account_id)`. A
  regeneration today would silently revert reviewed hand fixes.
- The `BINDINGS` map that PR #19 described, and that
  `docs/law-invariant-audit.md` claims exists, never landed on `main` (the
  landing PR #22 omitted `tools/generate_api.py`). Two hand-maintained copies
  of the operation set — generator map and `docs/coverage.json` — have already
  drifted apart once without any gate noticing.
- The v20 surface is finite and mature: 32 operations and 168 definitions in
  `docs/coverage.json`, cross-checked against a pinned OpenAPI revision, with
  a weekly release-notes watch (`tools/check_release_notes.py`) already
  detecting provider drift independently of the generators.

## Success criteria

- `tools/generate_api.py`, `tools/generate_models.py`,
  `tools/generate_variants.py`, `tools/fetch_website.py`, and
  `tools/test_generate_tools.py` are deleted; `tools/build_definition_fixtures.py`
  is deleted and `tests/definition_wire.rs` stands as a checked-in test file.
- No Rust contract changes: the `src/` and `tests/` diff is comment/header-only
  (generated-by framing removed), proven by the validation plan below.
- `docs/coverage.json` is the single source of truth for the operation and
  definition set; `tools/check_coverage.py` and the wire-fixture, enum, and
  tagged-variant suites remain the gate that catches hand-editing drift.
- No document claims regeneration is possible or byte-identical.

## Approach

Freeze, don't rewrite. The generated files are accepted as-is as the starting
hand-maintained sources — including their hand-applied fixes — and only their
provenance framing changes. Verification moves entirely to the artifacts that
already check the code rather than produce it: the coverage ledger and gate,
the independently sourced definition fixtures, and the enum/tagged-variant
round-trip suites (which fail compilation when a hand edit drifts). Future
OANDA changes arrive through the release-notes watch and are applied by hand:
edit the DTO or method, update `docs/coverage.json`, and add or extend a wire
fixture in the same change, per OA-COVERAGE-01.

Rejected alternative: keep the generators but repair them (restore `BINDINGS`,
reconcile the `execute` signature, commit saved pages). That is a larger,
ongoing cost — page-scraping fragility, a second copy of the ledger, and a
regeneration proof CI cannot run — to protect against provider changes the
release-notes watch already surfaces.

## Steps

One PR implements this plan (one feature per PROC-REVIEW); this plan PR only
records the decision.

1. **Baseline.** On `main`, record green: `cargo test --all-features`,
   `cargo fmt --check`, strict Clippy, `RUSTDOCFLAGS='-D warnings' cargo doc`,
   `python3 tools/check_coverage.py`, and
   `python3 -m unittest discover -s tools -p 'test_*.py'`. This is the
   before-picture the removal must reproduce exactly.
2. **De-frame the sources (comment-only).** Remove generated-by framing:
   the header in `src/lib.rs` ("generated from OANDA's published pages"),
   per-file generated headers in `src/*.rs` and `src/models/*.rs`, and the
   "Generated by tools/build_definition_fixtures.py" line in
   `tests/definition_wire.rs` (its provenance note about the pinned spec
   stays — it describes the fixture data, not a runnable generator).
3. **Delete the tooling.** Remove the five files named in Success criteria.
   Confirm nothing else references them (`rg generate_api|generate_models|generate_variants|fetch_website|build_definition_fixtures|test_generate_tools`
   outside `docs/law-invariant-audit.md` history rows, which Step 5 handles).
4. **Freeze the fixture builder's output.** `tests/definition_wire.rs` needs
   no code change beyond Step 2; its 168 fixtures and 66 required-field
   negatives keep running as ordinary tests.
5. **Rewrite the docs.** `docs/coverage.md`: replace the regeneration and
   identity-binding paragraphs with the hand-maintenance procedure above.
   `docs/law-invariant-audit.md`: mark the generator rows (#8, #9) historical —
   the fabrication and positional-binding failures they record happened and
   motivated contracts now enforced by tests, but the generators themselves
   are gone; do not delete the rows. `README.md` and crate docs: drop any
   regeneration instructions if present.
6. **CI check.** `.github/workflows/ci.yml` already runs only the gate and
   offline tests, so no workflow change is expected; confirm the unittest
   discovery still passes with `test_generate_tools.py` gone (one fewer
   module, no import errors).
7. **Close the loop on #21.** Comment on #21 that item 2 (`BINDINGS` vs the
   ledger) is moot once this lands — there is no second copy to compare —
   and that item 1 (anchoring `Response`/`Rejection` checks to each method's
   own signature in `check_coverage.py`) remains open and proceeds as its
   own PR, since the gate stays.

## Validation plan

- `git diff main -- src/ tests/` shows comment/header changes only; any
  non-comment hunk is a stop-and-review finding.
- Full re-run of the Step 1 baseline, all green, including
  `python3 tools/check_coverage.py` reporting 32/32 operations and 168/168
  definitions tested.
- `python3 -m unittest discover -s tools -p 'test_*.py'` passes with the
  generator test module removed.
- Manual check: `rg` for `generate_` and `regenerat` across `src/`, `docs/`,
  `README.md`, and `.github/` returns only the historical audit rows.

## Risks / open questions

- **Losing the second reader.** `build_definition_fixtures.py` built fixtures
  from the pinned OpenAPI spec, an independent document from the website, so
  a generator-dropped field could not vanish from both. Freezing keeps the
  fixtures as tests but ends that regeneration; a future hand-added field
  needs a hand-added fixture, enforced only by review and the coverage gate.
  Accepted: the pinned spec stays in `spec/official/` for manual cross-checks.
- **Tedious surfaces.** 503 enum values and 55 tagged variants are painful to
  edit by hand; the round-trip suites fail compilation on drift, which is
  the safety net. No mitigation beyond keeping those suites mandatory in CI.
- **No open questions.** The operator directed this approach; the only
  sequencing choice (separate PR from #21 item 1) is settled in Step 7.
